# 田块拆并接续与用水来源审计 v1（irrigation.land_water）

合作社在季中拆分或合并田块。旧田块退出登记后，土壤里的水留在原地；同样面积的
新田块从不同旧田块接管土地，后续缺水量与旧灌溉水的去向都可能不同。本模块在完全
保留现有日水账口径（`irrigation.balance.step` 的输水效率、入渗上限、径流、容量
渗漏、实际 ET、缺水与建议顺序、精确有理数计算）的前提下，按约定的**均匀混合
模型**逐股追踪历史来水，支持复核人员沿田块沿革回答两类问题：某笔历史进水最后
去了哪些田块或损耗；水账中某项损耗由哪些历史进水构成。

公开接口为 `irrigation.land_water.run(data)`，命令为
`soil-water-land --source INPUT --output REPORT`，二者共用同一业务逻辑，仅用
Python >=3.11 标准库。全部计算使用 `fractions.Fraction` 精确有理数，不使用浮点
或容差；**输入对象不会被修改**，非法数据抛 `ValueError`，文件错误可抛 `OSError`。
命令沿用既有严格 JSON 读取（重复键、`NaN`/`Infinity` 一律拒绝）与“全部计算
完成后原子新建报告”的约定：成功退出 0；输入或文件错误退出 2 并给出可读错误，
目标已存在时保留原文件、绝不覆盖、不发布半份报告。`run`、`plan`、
`meter_ledger`、`reuse_water` 与四个既有命令的接口与命令契约保持不变。

## 1. 输入结构

输入根对象恰好包含 `fields`、`weather`、`applications`、`repartitions`、
`audit_sources`、`audit_sinks` 六个键，任何未声明字段（含拼写错误）一律拒绝；
拆并批、交接行、查询行等新增对象同样不接受未声明字段。后三个数组可以为空。

- `fields`：期初在册田块，字段与现有核算完全相同（`id`、正整数 `area_m2`、
  `capacity_mm`、`infiltration_mm`、非负整数 `opening_mm`、`threshold_mm`、
  `target_mm`、1..1000 的 `efficiency_permille`，限值关系
  0≤threshold≤target≤capacity、opening≤capacity）。
- `weather`：全局严格升序、连续的气象日，最多 **60** 天；字段沿用现有口径
  （规范 `YYYY-MM-DD` 日期、非负整数 `rain_mm`/`et_mm`）。
- `applications`：沿用 `field_id`、`date`、`gross_mm`；每个田块日最多一条，
  只允许引用**当日有效（在册）**的田块，缺行视为零。毛供水为非负整数。
- 规模上限：任一时点最多 **200** 个在册田块；整个窗口内期初与新增田块合计
  最多 **1000** 个；交接明细（全部批次的 moves 行数）最多 **3000** 条。
- 日期与整数校验沿用现有口径：所有整数按 `type is int` 校验，**bool 一律
  拒绝**；字符串身份为非空字符串并**保留原值**，不做 strip、大小写或 Unicode
  归并。

### 1.1 repartitions（拆并批）

每个生效日最多一批，**不能在首日或气象窗口外生效**。每批恰好含 `date`、
`new_fields`、`moves`，后两项均非空。

- `new_fields`：沿用 `fields` 的田块参数与限值口径，**唯独不接收
  `opening_mm`**（新田块的期初水深由交接水量除以接管面积得到）。新 id 在整个
  窗口内不得复用，包括已退出的 id。
- `moves`：每行只有 `from_field_id`、`to_field_id`、正整数 `area_m2`；同一
  批每个有向田块对最多一条。转出方必须是**前一天仍在册**的田块，转入方必须是
  **本批的新田块**。
- 任何有转出的田块整体退出，其转出面积之和必须**恰等于原面积**；每个新田块的
  转入面积之和必须**恰等于自身面积**。未被转出的田块及其原属性继续生效。
- 整批在当日降雨与供水**之前同时生效**：不能让本批新田块再转出，也不能按
  moves 的排列逐条改变转出方的可用面积或剩余水量（批次按面积守恒一次性结算，
  与数组顺序无关）。

### 1.2 audit_sources / audit_sinks（审计查询）

两个数组各最多 **12** 条，元素为恰好含 `date`、`field_id`、`kind` 的对象，
重复身份、失效田块日或与 `kind` 不相符的日期属于非法输入。

- 来源 `kind`：`initial`（首日土壤存量）、`rain`（有效田块日的降雨）、
  `irrigation`（有效田块日的毛供水）。
- 终点 `kind`：`delivery_loss`（输水损耗）、`runoff`（径流）、`drainage`
  （渗漏）、`et`（实际蒸散）、`storage`（末日仍在册田块的结存）。
- `initial` 只能查询首日在册田块；`storage` 只能查询末日在册田块；其余 kind
  只能查询当日在册田块。身份有效但水量为零的查询正常返回零值与空明细。

## 2. 交接与每日水账

### 2.1 土地交接（内部转移）

同一旧田块上一日期末储水与各来源份额，均**按面积比例**随土地转移。例如上一日
末储水 4mm 的田块转出 3m²，则该边交接 12L，旧田块不能另外保有这 12L。汇总
各转入边的水量后，除以接管田块面积得到其当天期初水深。交接是**内部转移**，
不能计入灌溉、降雨或损耗，也不出现在任何来源/终点对账中。即使继承的期初水深
高过新田块容量，也**不得预裁**；超量按现有 `balance.step` 的当日渗漏顺序反映。

### 2.2 每日水账

当天各田块的输水效率、入渗上限、径流、渗漏、实际 ET、缺水量、结存与建议，
全部使用现有田间水账顺序和精确有理数口径，逐字段保留现有 `daily` 的字段与
格式（`advised_next_gross_mm` 为整数，其余 `*_mm` 为 Fraction 规范字符串）。

## 3. 均匀混合归因模型

来源与终点均用 `(date, field_id, kind)` 标识。首日土壤存量为 `initial`；每个
有效田块日的降雨为 `rain`、毛供水为 `irrigation`。每个有效田块日的输水损耗、
径流、渗漏、实际蒸散分别为 `delivery_loss`、`runoff`、`drainage`、`et`；
末日仍在册田块的结存为 `storage`。其余日末结存与土地交接都只是**途中存量**，
不是终点。归因严格按下列顺序：

1. **输水损耗只来自本次毛供水**：毛供水先乘效率，损耗整笔归于当日
   `irrigation` 来源。
2. **到田水与当日雨水先混匀**：径流按它们在混合水中所占比例带走水，**不能
   带走期初存量**；入渗水按同一比例拆成雨水与灌溉水份额。
3. **入渗水与期初水混匀**：随后记录渗漏、实际 ET 和剩余土壤水，均按该混合水
   的来源占比分配。没有水时不开除法，也没有非零来源贡献。这里追踪水本身，
   ET 也是终点，未满足的 ET 不算出水。
4. 同一笔来源可以从多个前身（经多次拆并）重新汇入同一终点，须合计其全部贡献。

两个方向的对账恒等式（精确成立，不用容差）：

- 每个终点的各来源贡献之和等于该处水账的水量；
- 每个来源落到所有终点的水量之和等于其原来进水量。

单查一端也必须追到另一端的全部非零贡献，不以另一组查询为过滤条件；嵌套明细
只列非零贡献。

## 4. 报告（schema_version = 1）

业务排序与输入数组顺序无关。除整数建议值外，所有 `*_mm` 数量与全部升数都用
Fraction 规范字符串输出，包括整数和零（例如 `"4"`、`"0"`、`"5/2"`，绝不出现
小数点或指数）。

- `daily`：按 `(date, field_id)` 列出所有**当日在册**田块的日水账，保留现有
  `daily` 的全部字段；退出日不产生旧田块账，生效日即产生新田块账。
- `land_transfers`：按 `(date, from_field_id, to_field_id)` 列出**每条实际
  交接边，包括水量为零的边**；字段为这三个身份、整数 `area_m2` 和
  `water_litres`（Fraction 字符串）。
- `audit_sources`：按查询身份 `(date, field_id, kind)` 排序，每行含该身份、
  `water_litres` 及 `sinks`；`sinks` 按终点身份排序，列出各终点身份与归于该
  来源的 `water_litres`。
- `audit_sinks`：同理，每行含终点身份、`water_litres` 和按来源身份排序的
  `sources` 明细。
- `system_balance`：窗口合计的 `initial_litres`、`rain_litres`、
  `irrigation_litres`、`delivery_loss_litres`、`runoff_litres`、
  `drainage_litres`、`et_litres`、`storage_litres` 和 `residual_litres`。
  余额 = 三项进水总和 − 四项外流（输水损耗、径流、渗漏、ET）− 末存，必须
  精确为 `"0"`，且与选择哪些审计查询无关。未满足 ET 与供水建议不能记成实际
  外流。

## 5. 边界

本模块是对给定气象与实际灌溉记录的离线核算与审计，不选择供水计划、不预测未来
天气、不操作设备，也不读写计量台账或回用水台账。mm×m²=升，无隐式单位换算。
不做污染物/盐分追踪、地下水交换或作物模型；ET 是调用者给定值。
